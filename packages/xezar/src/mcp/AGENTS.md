# Guidance for `packages/xezar/src/mcp/`

Cross-repository rules and the task-routing index are in the root `AGENTS.md`.

## MCP server (`xezar mcp` bridge, the tools a project leader calls)

The reference's tables and `mcp-api.json` are regenerated from the real registry by `mcp-api-doc.test.ts`; a tool change without `npm test -- packages/xezar/src/mcp/mcp-api-doc.test.ts -u` fails the suite, and a new tool action needs its inventory records in `tools/api-coverage.testkit.ts`. **A project leader uses these tools only – never the cockpit UI or `/api/v1`** (owner rule, 2026-09-15, #439). It is attached so events are pushed (`<channel source="xezar">` for Claude Code, a cross-session message into its own inbox for Qwen Code, sent by the session's own bridge (`qwen-messaging.ts`) – on Linux and macOS only, because Qwen Code opens no inbox on Windows, so a Windows Qwen Code leader reads with `leader_events` (#1086), a started turn for Codex); `leader_events` read is the fallback for a leader that is not attached. Attaching is an MCP action too (#450): `leader_events` `attach` / `stop` / `status` act for the calling session only, with the client derived from that session and never taken from an argument. GitHub facts (labels, verdicts, merge state) come from `gh`, which the MCP does not carry. Leader-facing text that sends a leader to the cockpit or HTTP is a bug; `leader-mcp-only.test.ts` pins the runtime strings. **A Claude Code leader only receives pushed events when launched with `claude --dangerously-load-development-channels server:xezar`** — without that flag it must read with `leader_events` `read` instead. Per-client leader setup and launch (Claude Code, Qwen Code, Codex) is documented once, for the end user, in `docs/guide/13-mcp-leader.md`; do not restate those steps here. **Windows (#963):** the service listens on an authenticated named pipe instead of a Unix socket (`pipe-endpoint.ts`, `pipe-auth.ts`; the folder check is `platform/private-dir.ts`); an elevated xezar serves only an elevated leader, through the administrators-only `ipc-admin` folder next to `ipc`, and a cockpit and leader that differ in elevation are refused with a message that says so (#980). Tests drive those rules on every OS through `McpServiceOptions.pipe`.
