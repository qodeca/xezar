# Guidance for `packages/xezar/src/runs/`

These rules are the full task-routing guidance moved from the repository root. Root `AGENTS.md` retains the routing index and canonical cross-repository rules.

## Runs store / state persistence

Plain files in `.local/xezar/`, no DB: `runs.json` index (zod-validated, atomic tmp+rename, debounced save) plus one append-only NDJSON event file per run. New `RunRecord` fields must be optional so old files still parse; corrupt files degrade to fresh, never crash. **Retention is count-based, not time-based**: the newest 300 non-archived and newest 500 archived runs are kept, and `pruneOldRuns()` deletes everything older — the record, its event NDJSON, its handoff journal and its images — silently, when a run is created. Changing either count or the deletion set is breaking (`BACKWARD_COMPATIBILITY.md` § 3). A **queued** run's prompt stays editable until the scheduler picks it up (pre-rename issue 472): `task` plus the optional `queuedMessages` stack are folded into `{{task}}` at dequeue, and that fold is read-only — never write it back to the record. The store is also the in-process event bus for SSE. Its cross-project sibling on the wire is `GET /api/v1/workspace/runs-index`, whose row is deliberately NOT `RunRecord` (`runIndexEntrySchema`): slim by design, it omits `steps[]` and `workflowDef` and instead carries server-DERIVED answers the browser could not cheaply compute across projects — `runner` (resolved), `runnerInherited?`, `model?` and `stepBackends?`. Adding a field there is cheap; reaching for the fat record is what that shape exists to prevent.
