# Guidance for `packages/xezar/src/runs/`

Cross-repository rules and the task-routing index are in the root `AGENTS.md`.

## Runs store / state persistence

Plain files in `.local/xezar/`, no DB: `runs.json` index (zod-validated, written through `writeFileAtomicSync` – see `packages/xezar/src/platform/AGENTS.md` – debounced save) plus one append-only NDJSON event file per run. The event file is read line by line (`forEachLineSync`), never as one string: a long run's log can pass the runtime's ~512 MB string ceiling, and the whole-file read's error used to land in the "no file yet" catch as an empty history — a blank transcript and `rehydrateSeq` restarting the numbering at 1 (#942). That catch stays: a run with no file yet has no events. New `RunRecord` fields must be optional so old files still parse; corrupt files degrade to fresh, never crash. Degrading is per record: `open()` keeps every row that parses, copies an index that did not load cleanly to `backups/runs.json.bak` before any save replaces it, and reports it through `loadedCleanly`, which every sweep that reads "not in the store" as "unwanted" must check first. **Retention is count-based, not time-based**: the newest 300 non-archived and newest 500 archived runs are kept, and `pruneOldRuns()` deletes everything older — the record, its event NDJSON, its handoff journal, its images and its author-evidence snapshot (`<id>-evidence/`, #933) — silently, when a run is created. Changing either count or the deletion set is breaking. A **queued** run's prompt stays editable until the scheduler picks it up (pre-rename issue 472): `task` plus the optional `queuedMessages` stack are folded into `{{task}}` at dequeue, and that fold is read-only — never write it back to the record. The store is also the in-process event bus for SSE. Its cross-project sibling on the wire is `GET /api/v1/workspace/runs-index`, whose row is deliberately NOT `RunRecord` (`runIndexEntrySchema`): slim by design, it omits `steps[]` and `workflowDef` and instead carries server-DERIVED answers the browser could not cheaply compute across projects — `runner` (resolved), `runnerInherited?`, `model?` and `stepBackends?`. Adding a field there is cheap; reaching for the fat record is what that shape exists to prevent.

**Another task's evidence (#933, `author-evidence.ts`).** A run started with `evidenceFromRunId` gets, at every agent step and at a Continue that opens a fresh session, a size-limited copy of the named task's evidence folders (`runEvidenceRoots`) and handoff in `runs/<id>-evidence/`, and the same files quoted in the opening message, with every truncation and omission named. The engine reads the source folders itself; they are never added to `additionalDirectories` (on Codex each entry is a WRITABLE root), and the copy lives under `runs/`, a root every step already has. Read the id from the RECORD, never from a rebuilt input, so recovery, Continue and variants cannot drop it.

## Run process sweep (`run-process-sweeper.ts`, #943)

`run-process-sweeper.ts`, `run-process-ledger.ts` and `run-process-report.ts` stop what a run started. Owner decision 2026-10-19: every way xezar stops a task stops what it started.

- **When it runs.** `RunManager` hands the run to its `RunProcessSweeper` when xezar pauses a run for its memory limit, cancels it, closes a session the agent had not ended (the idle close, the user's Finish, a gated bound that would otherwise wait out the idle close, a read-only step's bound finish), or a step hits its time limit. So it does when the runner's EOF watchdog has to stop a backend that did not exit after its session closed (`AgentRunResult.stoppedAfterClose`), and after an agent error (an `error` event or a failed session) – those two at once, like a time limit, before anything else of the run starts (a retry, the next step). The sweeper stops what the run started and leaves one `note` naming it (command lines redacted in full, then cut to 200 characters).
- **After a crash (#982)** the engine that starts next does the same for every run the record still calls `running`, in `recover()`, before the resumed turn starts (the Continue waits for the pending sweep). On Windows and macOS that needs the earlier engine's ledger, so each run's ledger is saved beside its files as `runs/<runId>.processes.json` (recorded pids with their start times, and the Git Bash groups; never the root pin) whenever it gains an entry, and every 10 s while it holds something. It is removed when the run ends, is cancelled or paused, and at start-up for every run that is not `running`. An unreadable file means nothing to sweep. Linux needs no file.
- **Proof is only xezar's own.** On Linux the exact `XEZ_TASK_ID=<runId>` entry in `/proc/<pid>/environ`; on Windows and macOS the run's ledger, recorded from the sampler's process tables (`onProcessTable`) with the root pinned by start time. On Windows, while a ledger holds something and Git for Windows is installed, each sampler read is followed by one read of Git's `ps`, so the ledger also records the MSYS process group each of the run's Git Bash shells leads; at a stop the group's members count when their Windows process started no earlier than the leader, and a group whose leader pid now names another process counts for nothing (#963). Never a name, working folder, command line, port or temp folder, and never for authorization: it is best-effort cleanup, not a containment boundary (macOS misses a process that detaches and loses its parent between two reads).
- **macOS reads once more before a cancel or a memory-limit pause** (`beforeStop`, at most 2 s), and only then stops the session: a program the agent started after the last sampler read is tied to the run only through its parent, and the stop orphans it (#963). A step's time limit and the EOF watchdog are enforced inside each runner, so there a program started within the last ~2 s stays best effort; the idle close and Finish read nothing first either (an idle session's programs were recorded long before). Linux and Windows stop at once (Windows reads the tree before it kills anyway).
- **Identity is checked at every signal.** A pid is signalled only while its start time still matches.
- **What is never swept.** Programs xezar opens for the user (`launchDetached`, `launchCmd`: an editor, a terminal, a browser) never carry `XEZ_TASK_ID`, so they are never attributed to a run. A run whose agent ends it cleanly – `XEZ:DONE` and a backend that then exits – is never swept. An in-process engine failure (`engine crashed`) is not swept either; only a run left `running` by an engine that exited is swept at the next start.
- **Bounds.** Sweeps are enrolled through `trackRun`, one per run at a time, capped at 10 s (30 s for the start-up sweep after a crash, `RESTART_SWEEP_CAP_MS`, #982). A Continue or a fresh body waits for a pending one, for at most its cap, before it starts anything – a pass still running past the cap goes on as best effort and stays identity-checked. A Windows or macOS sweep is skipped outright when the run's ledger is empty, since each Windows pass can start a few short PowerShell runs.
- **Check steps are out of reach.** They keep today's environment (no `XEZ_TASK_ID`; #1006 adds only `XEZ_PR_NUMBER`, which the sweep never reads), so their detached leftovers are out of reach until the kit changes.
