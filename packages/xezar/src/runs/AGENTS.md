# Guidance for `packages/xezar/src/runs/`

Cross-repository rules and the task-routing index are in the root `AGENTS.md`.

## Runs store / state persistence

Plain files in `.local/xezar/`, no DB: `runs.json` index (zod-validated, written through `writeFileAtomicSync` – see `packages/xezar/src/AGENTS.md` § Platform layer – debounced save) plus one append-only NDJSON event file per run. New `RunRecord` fields must be optional so old files still parse; corrupt files degrade to fresh, never crash. **Retention is count-based, not time-based**: the newest 300 non-archived and newest 500 archived runs are kept, and `pruneOldRuns()` deletes everything older — the record, its event NDJSON, its handoff journal, its images and its author-evidence snapshot (`<id>-evidence/`, #933) — silently, when a run is created. Changing either count or the deletion set is breaking. A **queued** run's prompt stays editable until the scheduler picks it up (pre-rename issue 472): `task` plus the optional `queuedMessages` stack are folded into `{{task}}` at dequeue, and that fold is read-only — never write it back to the record. The store is also the in-process event bus for SSE. Its cross-project sibling on the wire is `GET /api/v1/workspace/runs-index`, whose row is deliberately NOT `RunRecord` (`runIndexEntrySchema`): slim by design, it omits `steps[]` and `workflowDef` and instead carries server-DERIVED answers the browser could not cheaply compute across projects — `runner` (resolved), `runnerInherited?`, `model?` and `stepBackends?`. Adding a field there is cheap; reaching for the fat record is what that shape exists to prevent.

`run-process-sweeper.ts`, `run-process-ledger.ts` and `run-process-report.ts` stop what a paused, cancelled or timed-out run started. Their rules (proof only by `XEZ_TASK_ID` or the ledger, never by name, folder or port; best-effort cleanup, not a containment boundary) are in `packages/xezar/src/AGENTS.md` § Run process sweep.

**Another task's evidence (#933, `author-evidence.ts`).** A run started with `evidenceFromRunId` gets, at every agent step and at a Continue that opens a fresh session, a size-limited copy of the named task's evidence folders (`runEvidenceRoots`) and handoff in `runs/<id>-evidence/`, and the same files quoted in the opening message, with every truncation and omission named. The engine reads the source folders itself; they are never added to `additionalDirectories` (on Codex each entry is a WRITABLE root), and the copy lives under `runs/`, a root every step already has. Read the id from the RECORD, never from a rebuilt input, so recovery, Continue and variants cannot drop it.
