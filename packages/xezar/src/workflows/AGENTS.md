# Guidance for `packages/xezar/src/workflows/`

Cross-repository rules and the task-routing index are in the root `AGENTS.md`.

## Workflows (YAML chains, steps, retries)

The diff-first review gate is optional and off by default: the Settings → Agents toggle (`reviewGate` in `.xezar/config.json`) wins when set, otherwise only `XEZ_REVIEW_GATE=1` turns it on, and autonomous runs always skip it. Whether or not a run parks at `review`, xezar never auto-merges.

A step is agent (`prompt`/`skill`) XOR check (`command`); a file has `steps` XOR the portable `skills` shorthand — both enforced by zod refinements. `onFail.retry` may only reference an _earlier_ step (`stepsIssue`). `{{task}}` is the substitution token. A check step runs with the engine's own environment plus `XEZ_PR_NUMBER` when the run knows its PR (`checkStepEnv`, #1006) – removed, not inherited, when it does not – so a workflow can prepare the PR (check it out) before a read-only agent starts; it never gets `XEZ_TASK_ID` (src/AGENTS.md § Run process sweep), and a new check-step variable goes through `checkStepEnv` and `.env.example`. `quick-task` is the built-in zero-config workflow; built-ins always come back after delete. An agent step may set its own wall clock with `timeout` (#22) — the literal `none`, or a positive duration in `s`, `m` or `h` (`45s`, `90m`, `2h`) — resolved in one place, `stepTimeoutMs`; a check step may not carry it. An **absent** `timeout` is a protected default, not an unset value: the last (interactive) step stays uncapped and every earlier agent step falls through to the runner's 30-minute `DEFAULT_RUN_TIMEOUT_MS`, and changing that is a breaking change. An earlier agent step is `done` only when its last turn ends with `XEZ:DONE` (#317, `unfinishedStepReason`): it runs one turn and cannot wait for an answer, so a question, `XEZ:MONITORING` or plain prose fails it and stops the run instead of carrying on; such a step is therefore never taught `XEZ:MONITORING` — its contract (`agentContract` with `canMonitor: false`, `handoff.ts`) tells it to finish its own background work inside the turn, and the marker check stays as the safety net (#940), while a quick task, the last step and a Continue keep the monitoring paragraph; the last step keeps its interactive rules, and changing those is breaking too. One narrow exception (#933): in an AUTONOMOUS run a READ-ONLY step (`isReadOnlyStep`) never parks at `waiting` — when a nudge bound stops the re-prompting (an idle re-prompt or the spent budget, `autoContinueStop`), `finishStoppedReadOnlyTurn` closes the session from BOTH turn-end handlers, the step ends `done` and a note says it ended without `XEZ:DONE` and that anything its last message says it could not read or check is a gap; writing steps, non-autonomous runs, a memory-limit pause and `XEZ:MONITORING` keep their existing behaviour. The FIRST automatic `onFail` return re-enters the retry target by resuming that step's own recorded backend session and sending it only the failing output — the brief is not repeated (#676); the second return is the fresh session with the whole brief it has always been, an unreachable session falls back to a fresh spawn inside the same return with a `note` and no extra attempt — no recorded id, another backend, another agent account, a backend whose runner cannot resume at all (OpenCode) or a resume the backend refuses at runtime before the model said a word, and `onFail.max` and the terminal "after N attempts" message are untouched.
