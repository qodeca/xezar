# Guidance for `packages/xezar/src/server/`

Cross-repository rules and the task-routing index are in the root `AGENTS.md`.

## HTTP server & API routes

Hono app, binds `127.0.0.1` by DEFAULT; `--bind-host` may widen that for a server install. Hosted mode (`capabilities.localHandoff:false`, which 409s every local-machine mutator) turns on for a non-loopback bind OR `XEZ_REMOTE=1` (`resolveCapabilities` in `capabilities.ts`) – those two and nothing else. Never widen the default. A global `/api/*` request-origin guard (pre-rename issue 426) runs before every route except `/api/v1/health`: it rejects non-loopback `Host` headers (DNS-rebinding) in local mode — and in hosted mode every name except an IP literal, a public name the server install recorded, or one listed in `XEZ_ALLOWED_HOSTS` (`hosted-hosts.ts`; no recorded name ⇒ refused, the 403 names the variable) — and cross-origin mutating requests (CSRF) in both modes — zero-config, no token, so the same-origin cockpit and the Vite dev proxy pass untouched. The loopback test is `isLoopbackHostHeader` (anchored 127.0.0.0/8, missing Host = untrusted); never match it with a `127.` string prefix. Route invariants (chaining, middleware validation, `/api/v1`): root `AGENTS.md` § The HTTP API; read a validated body from `c.req.valid('json'|'param'|'query')`. The rejection shape is unchanged: `{ error }` with 400/404/409. CORS is deliberately enabled for `/api/v1/health` only (cross-origin discovery); never widen it. Likewise never relax the framing headers: every HTML page the service sends carries `Content-Security-Policy: frame-ancestors 'none'` and `X-Frame-Options: DENY` (`HTML_FRAME_HEADERS` in `static-ui.ts`, #1110), so no other site can show the cockpit's controls inside its own page. Keep that policy frame-ancestors only – a wider CSP would also govern the cockpit's scripts and styles. SSE endpoints replay from NDJSON then stream live, deduped by `seq`.

## Real-time events (live UI signals, replacing polls)

Two live channels: the SSE run/event stream (`/api/v1/workspace/events`, `packages/web/src/api/global-events.tsx`) and the **WebSocket subscription bus** (`/api/v1/ws`, `ws` lib server-side, native `WebSocket` client). The bus is the pattern for any new live signal instead of a `refetchInterval`. Its whole discipline is **demand-driven subscription**: a topic's server publisher starts on the `0→1` subscriber and stops on `1→0`, and one socket per cockpit ref-counts listeners per topic. **Subscribe at the scope that matches the data's demand lifetime, always return the unsubscribe (`useEffect(() => subscribeTopic(...))`), publish only on change** — a leaked subscription is a server publisher that never stops AND a component that keeps waking for a screen the user left. Per-view signals subscribe in the view; **session-global signals subscribe ONCE at the root**, not per reader — health is the worked example: one `useHealthSubscription()` controller in `GlobalEventsProvider` subscribes after bootstrap only for local mode, while `useHealth()` is a pure cache read the ~20 readers call without touching the socket. Remote mode must open no browser WebSocket because it cannot explicitly carry reverse-proxy credentials; it uses authenticated HTTP plus SSE reconciliation. One socket per local cockpit — never `new WebSocket` for a feature; add a topic. Liveness: server ping/pong reaping + app-level beat, client watchdog + reconnect. Topics are workspace-level (single-mount, never `/api/v1/p/`) and, because the upgrade guard admits any loopback origin (WS has no CORS), must only carry data safe for any local page.

## Project-scoped routes & contexts (`/api/v1/p/:projectId`, `/p/:projectId`)

One lazily built `{store, manager, dataDir, launchKey}` context per registered project, disposed on removal; a `missing` root is never instantiated (unknown id → 404, gone root → 409). Every project route is registered **once** in a chained family builder and mounted under both `/api/v1/<path>` (bound to the boot project) and `/api/v1/p/:projectId/<path>` — `route-parity.test.ts` walks the exported route manifest and asserts `/api/v1/x`, `/api/v1/p/<boot>/x` and `/api/v1/p/default/x` answer byte-identically, so a new scoped route without its alias fails the suite. `default` is the reserved boot alias and is never an allocated slug. Workspace-level routes (`/projects`, `/workspace/*`, `/fs/browse`) are single-mount and never scope-prefixed. The cockpit mirrors the split: every view lives under `/p/:projectId/`, flat legacy PAGE paths redirect to the boot project, and global settings sit outside the scope at `/settings/global`. Route invariants: root `AGENTS.md` § The HTTP API; `versioned-surface.test.ts` fails on any route outside `/api/v1`. The HTTP API is a protected surface: adding a route is additive, and changing or removing one is breaking.

## GitHub integration (issues/PRs tab, draft PRs)

Must degrade gracefully: no `gh`, no remote, offline all return `{ available: false, reason }` — never an error. `gh … --json` output is zod-validated at the boundary. `GITHUB_TOKEN` is the fallback when `gh` isn't authenticated. `createDraftPr` never throws; failures map to one-line human errors. `XEZ_DRY_RUN=1` fakes the PR URL.
