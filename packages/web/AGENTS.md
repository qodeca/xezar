# Guidance for `packages/web/`

These rules are the full task-routing guidance moved from the repository root. Root `AGENTS.md` retains the routing index and canonical cross-repository rules.

## Web UI (cockpit)

React 19 + Vite + Tailwind v4 + shadcn/ui; source lives in `packages/web/` (its own npm workspace, `@qodeca/xezar-web`, with the React/Vite/Tailwind deps in ITS manifest, not the root's), build output in ignored `packages/xezar/web/dist/`. Anything the server and the cockpit BOTH speak — the v2 protocol types, the `/api/v1/p/:projectId` scope helpers, and (as it grows) the typed API client — lives in the third workspace `packages/api-client/` (`@qodeca/xezar-api-client`), which must stay Node-free: no `node:*` import and no `@types/node`, because it is bundled into the browser AND imported by the Node service. Keep one global SSE connection and patch the TanStack Query cache in place; authoritative refetch happens on reconnect/visibility. Preserve light/dark/system theming, mobile safe areas, keyboard access, and unit coverage. **Three shared modules own the task tables and a change to either table goes through them, never around them.** `src/lib/task-columns.ts` is the one ordered description of the per-project desktop table — header, colgroup and every row consume `TASK_COLUMNS`, so a new column is three coordinated additions there and never an ad-hoc `<td>`. `src/lib/runner-label.ts` is the single backend id → product name map plus the pure text rules (`runnerLabel`, `modelLabel`, `stepBackendCount`, `taskRunner`); it exists because the same four pairs had been copied into five components, so a new backend or a new surface imports it rather than adding copy number six, and it is typed `Record<Runner, string>` precisely so a fifth backend is a compile error. `src/components/task-agent.tsx` holds the Tool Name / Model cells both tables render. Two invariants there are breakable without any test failing: the TEXT rules stay in `runner-label.ts` rather than in the cell components, because the phone card renders the same two facts as plain spans on a `font-mono` line and cannot host the components (the two had already drifted once); and `taskRunner`'s resolution order is duplicated server-side ON PURPOSE and the two must stay identical — `RunIndexEntry.runner` is resolved in the server because the cross-project index carries no `steps[]`, and BACKWARD_COMPATIBILITY.md makes resolving it client-side an explicit break. When `packages/xezar/web/dist` is missing the server answers every shell route with a built-in "The cockpit files are missing" recovery page that tells the user to reinstall (`packages/xezar/src/server/static-ui.ts`); it ships in every installation, so it never names `npm run build:web` — run that yourself in a source checkout (the server log says so).
