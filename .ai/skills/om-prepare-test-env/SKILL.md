# Repository test-environment notes

- Launch the built xezar server through `.ai/scripts/test-env-up.sh`; its app process must use `nohup` with stdin detached so it survives non-interactive bootstrap shells. This prevents a descriptor from reporting a server that is terminated as soon as the bootstrap command exits.
- Fresh worktrees have no workspace links or runtime dependencies. The generated entrypoint must run the compound `npm ci && npm run build` chain through `sh -c`, include `packages/contract/src` in its build fingerprint, and require `node_modules/zod/package.json` as a cache artifact. This prevents `@qodeca/xezar-contract` from resolving as missing/unknown during `tsc` and prevents a cached build from starting without runtime dependencies. Do not require `packages/api-client/dist`: the web build aliases that workspace to source and the root build does not emit that directory. Run `XEZ_AGENT_MODELS_LOCKED=1 sh .ai/scripts/test-env-up.sh --force` for locked-model QA.
- The boot isolates the agents' own USER-SCOPE config, not only xezar's home: `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `OPENCODE_CONFIG_DIR` are pinned to empty 0700 dirs under `.ai/qa/agent-home/` alongside the `XEZ_HOME` pin, and `ANTHROPIC_MODEL` is unset because it outranks every settings file. The cockpit seeds each runner's model from that agent's native settings file, so without this a QA boot shows the operator's own configured models and a spec asserting an unset model passes in CI while failing on their machine. Use `OPENCODE_CONFIG_DIR`, never `XDG_CONFIG_HOME`: the latter is machine-wide and deauthenticates `gh` inside the boot. These are the vars `agentHomePaths()` honours (`packages/xezar/src/paths.ts`); a fourth agent home added there needs pinning here too.
- The sandbox is wiped and recreated on every COLD boot, and the pins are part of the reuse fingerprint (`environment.agentHome`), so an instance booted with different pins is never reused. Manual QA that saves a file through Settings → Agent config writes into that sandbox — it is discarded on the next cold boot, so do not treat anything left there as durable, and do not run a real `codex login` / `claude` login while the boot env is active unless you mean to write credentials under `.ai/qa/`.
