# Repository test-environment notes

- Launch the built xezar server through `.ai/scripts/test-env-up.sh`; its app process must use `nohup` with stdin detached so it survives non-interactive bootstrap shells. This prevents a descriptor from reporting a server that is terminated as soon as the bootstrap command exits.
- Fresh worktrees have no workspace links or runtime dependencies. The generated entrypoint must run the compound `npm ci && npm run build` chain through `sh -c`, include `packages/contract/src` in its build fingerprint, and require `node_modules/zod/package.json` as a cache artifact. This prevents `@qodeca/xezar-contract` from resolving as missing/unknown during `tsc` and prevents a cached build from starting without runtime dependencies. Do not require `packages/api-client/dist`: the web build aliases that workspace to source and the root build does not emit that directory. Run `XEZ_AGENT_MODELS_LOCKED=1 sh .ai/scripts/test-env-up.sh --force` for locked-model QA.
- The boot isolates the agents' own config dirs, not only xezar's home: `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `XDG_CONFIG_HOME` are pinned to empty dirs under `.ai/qa/agent-home/` alongside the `XEZ_HOME` pin. The cockpit seeds each runner's model from that agent's native settings file, so without this a QA boot shows the operator's own configured models and a spec asserting an unset model passes in CI while failing on their machine. These are the vars `agentHomePaths()` honours (`packages/xezar/src/paths.ts`); a fourth agent home added there needs pinning here too.
