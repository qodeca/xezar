## 🐛 Fixes

- 🐛 **The ⌘K palette focus wait no longer races its own exit animation.**
  `progressive-history.e2e.ts` pressed Ctrl+K while the previous palette was still animating
  closed. Radix keeps a closing dialog mounted, so the press reopened the SAME node and its
  focus-on-open — the thing that puts focus in the input — never ran again: the palette sat open
  with `document.activeElement` on `BODY` for the whole 25 s wait (CI run 35526301088, 1 of 459
  specs). The helper now waits for the palette's own closed state before pressing, and asserts
  focus through the input's `combobox` role rather than a `cmdk-input` attribute on
  `activeElement`. Part of #671.
- 🐛 **The store-fixture scan's exemption is scoped to the store's own variable.** It cleared a file
  on ANY `.close()`, so a fixture whose `RunStore` was never closed read as clean because it closed
  an http server, a watcher or a service handle instead. Scoping the exemption to the variable the
  open bound surfaced seven such pre-existing fixtures, now listed beside the original 69; the
  scan's named break proves an unrelated `srv.close()` no longer clears a file. Part of #671
  (#765 re-check, Minor 2).
