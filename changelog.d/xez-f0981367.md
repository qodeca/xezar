## 🐛 Fixes

- 🐛 **The ⌘K palette focus wait no longer races its own exit animation.**
  `progressive-history.e2e.ts` pressed Ctrl+K while the previous palette was still animating
  closed. Radix keeps a closing dialog mounted, so the press reopened the SAME node and its
  focus-on-open — the thing that puts focus in the input — never ran again: the palette sat open
  with `document.activeElement` on `BODY` for the whole 25 s wait (CI run 35526301088, 1 of 459
  specs). The helper now waits for the palette's own closed state before pressing, and asserts
  focus through the input's `combobox` role rather than a `cmdk-input` attribute on
  `activeElement`. Part of #671.
- 🐛 **The store-fixture scan's exemption is scoped to the store's own variable.** It cleared a file
  on ANY `.close()`, so a fixture whose `RunStore` was never closed read as clean because it closed
  an http server, a watcher or a service handle instead. Scoping the exemption to the variable the
  open bound surfaced seven such pre-existing fixtures, now listed beside the original 69; the
  scan's named break proves an unrelated `srv.close()` no longer clears a file. Part of #671
  (#765 re-check, Minor 2).
- 🐛 **The per-dataDir todos watch test no longer loses its one measured write.**
  `todos.test.ts` wrote `todos.json` once after a fixed 400 ms settle; under the full suite's load
  macOS was still registering the fresh `fs.watch`, so the write was dropped, not delayed (#204),
  and the wait timed out (`expected 0 to be greater than 0`). The test now proves both watches live
  with a delivered event — the file's own `writeUntilDelivered` helper — before measuring, and
  rewrites only A until one lands, so `b` staying silent is still the whole claim. Part of #671.
- 🐛 **The test-env launcher no longer probes a port and releases it before the app binds.**
  `scripts/test-env-up.sh` proved a port free (`port_free`/`free_port`), released it, then started
  the app on it — the exact TOCTOU #238 removed from the product. Under the gate's parallel lanes a
  peer process took the probed port first (`test-env-launcher.test.ts`, `EADDRINUSE
  127.0.0.1:55144`), and a boot that trusts the probe polls a URL with nobody behind it. The app now
  owns port selection — `--port` is a request, a taken port moves it to the next one and it prints
  the port it holds — and the launcher reads that line instead of probing. Part of #671.
