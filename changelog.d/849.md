## 🔒 Security

- 🔒 **The four read-only kit workflows can no longer write through the shell.** `code-review`,
  `design-review`, `qa` and `business-analysis` granted plain `Bash` in `allowedTools` with no
  `bashAllowlist`, so a "read-only" reviewer could still write through the shell on every backend
  even though `Edit`/`Write` were already absent — through `git`, that includes writing to a
  branch. Each now carries a `bashAllowlist` of the commands its own skill actually needs (`git`,
  `gh` where the role posts PR comments or labels, `npm` where it exercises code, the kit's own
  check scripts, and read-only text/file inspection). On Claude the step now gets one
  `Bash(<prefix>:*)` entry per allowed command instead of unrestricted `Bash`; on pi, which has no
  command-prefix mechanism, the whole `bash` tool is dropped for these four roles — route them to
  Claude or Codex there. `research.yaml` is unchanged, its `Write` grant is intentional. (#849)
