## ✨ Features

- ✨ **A project leader can switch agent backends off and on over MCP, and clear a sign-in
  problem.** `project_config`'s `set_provider_enabled` and `retry_provider` used to exist only to
  refuse; both are real changes now and go through the same routes the cockpit's own Providers card
  uses. Switching a backend off applies to **every project on this machine** and takes effect at
  once: the next task simply is not offered that backend, with no restart. Switching one back on
  re-enables a backend the person had deliberately turned off, so it is worth being sure before
  either. "Try again" after a sign-in problem works too, and the leader never sees — or needs — the
  id of the incident it clears: the tool reads the current one itself, and if a newer problem
  arrives in between, the answer is the same "refresh and try again" the cockpit gets.
  **Connecting a backend is still not something a leader can do**: that opens a login window on the
  person's own machine, which stays a person's job. (#677)

## 🐛 Fixes

- 🐛 **A correction to what the leader is told about dismissed provider incidents.** The advice
  added in the previous release — read a shared preference, change one part of it and send the whole
  thing back — does not work for the list of dismissed provider sign-in incidents, because reading it
  reports which backends were dismissed and deliberately withholds the incident ids that a change
  needs. Writing that one preference therefore replaces every dismissal there is; sending an empty
  object clears them all, and leaving it out keeps them. The wording in the tool and in the
  documentation now says so. (#677)
