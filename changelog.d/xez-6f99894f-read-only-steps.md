## 🔒 Security

- 🔒 **A read-only step is now read-only on Claude Code and Codex.** A step whose tool list names neither `Edit` nor `Write` — the review, QA and analysis shape `[Read, Grep, Glob, Bash]` — now removes `Edit`, `Write` and `NotebookEdit` on Claude Code with `--disallowedTools`, so neither `XEZ_APPROVAL_GATE=1` nor a project's own `permissions.allow` brings them back, and runs Codex in its `read-only` sandbox on start and on resume instead of full access. Writing steps are unchanged. OpenCode still does not apply a read-only step, and plain `Bash` in the list remains a shell on Claude Code and pi until a `bashAllowlist` narrows it; the per-backend table is in `AGENT_PROTOCOL.md`. Breaking for a Codex workflow that wrote files from a step listing neither tool (`BACKWARD_COMPATIBILITY.md`). (#849)
