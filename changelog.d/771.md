## 🐛 Fixes

- 🐛 **Skills → Refresh says what actually happened instead of always reporting success.** With the
  team-skills origin unreachable the button toasted "Team skills refreshed" although nothing had
  been fetched — and the catalog block right below it, the one whose own sentences send the reader
  to this button, still read `Check is stale`. `POST /api/v1/skills/refresh` now answers
  `{skills, sources}` with one `{repo, ok, reason?}` per configured source, so the toast can report
  a failure in the server's own words in the danger tone, and a partial result ("Refreshed 1 of 2
  team skills sources — …") as the partial it is. The shape change is recorded in
  `BACKWARD_COMPATIBILITY.md` § 2; the MCP `project_config:refresh_skills` action keeps its
  `skills` key and gains `sources`. (#771)
