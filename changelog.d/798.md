## ✨ Features

- ✨ **The instance mode is a setting you can change, from Settings → Terminal or from a project
  leader.** `cli.instance` — whether one xezar opens every project you have registered or serves
  only the project it started in — has been stored in `~/.xezar/config.json` since it shipped and
  was editable nowhere but the file. A new global Settings section, Terminal, now offers the three
  states (one cockpit for every project, one cockpit per project, or follow `XEZ_INSTANCE`), and
  the MCP `project_config` action `set_workspace_config` writes the same key through the same
  route, so the cockpit and a leader produce the identical file. `workspace` remains the default
  and nothing on that path changes. The control is honest about two things a settings pane usually
  is not: the mode is decided when xezar starts, so it says the change applies at the next start
  rather than pretending to be live, and a cockpit already narrowed to one project is told the
  narrowing wins there instead of being shown a stored value that is not what it is doing. (#467)
