## 1. Scope

**Governs:**

- every change merged between `v0.13.1` and the release candidate that is not the MCP feature
  (the inventory in § 2);
- the release act: the changelog section, npm, the git tag and the GitHub Release.

**Does not govern:**

- the MCP feature: F-01..F-22, N-01..N-10, A-01..A-23 and the eight clauses. Closing those is
  [#119](https://github.com/qodeca/xezar/issues/119), whose result is
  [`mcp-definition-of-done-record.md`](../features/mcp-server/mcp-definition-of-done-record.md):
  measured on `ed579e63` on 2026-09-12, **five of the eight clauses hold and clauses 2, 3 and 8 do
  not**;
- whether 0.14.0 may ship before #119 is closed. That was question Q1, and the owner answered
  it: #119 closes first (§ 5).

**Overlap.** Some items are both: #271 is an MCP isolation fix (A-02..A-04), and #272 restores
F-15. For those, both documents apply. This document never relaxes an MCP clause. It adds the
release-level question: *does the property hold on the revision that ships?*

## 4. How this is assessed

- **One revision.** R-1 to R-9 are assessed on C, like clause 2 of the MCP DoD. R-10 is assessed
  after publication, and about C.
- **Evidence from another revision.**
  - For test results, it does not count. The gate on C re-runs them.
  - For the two human checks (the R-6 walk-through and the R-8 review), evidence from an earlier
    revision X counts only when the recorded `git diff X..C` over the files concerned is empty. For
    R-6 those files are `CONTRIBUTING.md` and every `package.json` and lockfile. For R-8 they are
    the surface's own files.
- **What evidence looks like:** the SHA, the exact command, the result, and the hash and location
  of the full log. Logs stay private in the release task's evidence directory
  (`.local/xezar-tasks/<runId>/`). The public result is a completion record,
  `docs/releases/0.14.0-completion-record.md`, which gives each clause a verdict and cites C.
- **Verdicts:**
  - **PASSED**, with evidence;
  - **FAILED**;
  - **EXCEPTION**, only with a written reason and the owner's approval. It is listed in the
    release notes as a known limitation.
- **No evidence means FAILED.** It is never "assumed passed". UNKNOWN is not a pass.
- **The release is done** when every clause is PASSED or an approved EXCEPTION, and Q1 is
  answered.
