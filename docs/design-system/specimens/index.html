Specimens

Static pages that show what the cockpit looks like. They open from disk, need no build, no server and no network, and never import the app's code. Every colour comes from ../cockpit.css, the same token sheet the drift test compares with packages/web/src/styles/index.css.

How to read a specimen. The bar at the top mirrors the cockpit's appearance preferences: theme (dark is the default, .light flips it), accent, density and reading width. Each frame below a label shows one token, component or pattern, with every state the code has. The written rules live in the Markdown next to this folder – start at README.md.

What the bar controls

ControlCockpit equivalentWhat changes
Toggle theme.light on <html>, stored as xez-themeThe 26 tokens that .light overrides. Everything else stays.
Accentdata-accent="violet"--primary, --primary-foreground, --ring.
Densitydata-density="roomy", "compact" or "ultra"--spacing, the unit behind every Tailwind size utility. The specimen shows it on the density demo in Foundations.
Widthdata-width="wide"--measure, the reading width of long text. See the layout frame in Foundations.

Rules the specimens follow

  • No raw colour outside the token sheet. A specimen that needs a colour names a token.
  • No sideways scroll at 375 px. Wide tables sit inside .table-scroll.
  • Motion respects prefers-reduced-motion: spinners, pulses, skeletons and shimmer stop.
  • Icons come from the inline Lucide sprite in icons.js at the cockpit's sizes: 16, 14, 12 and 10 px.
  • Fonts load from packages/web/src/assets/fonts/ by relative path. Move this folder and the fonts fall back to the system stack.
