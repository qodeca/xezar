Agent accounts – what onboarding needs to see

Settings → Agent accounts, for #819 PR 9. After a project is set up, a person opens this pane to answer three questions: which logins does each agent have, which one do tasks use, and did my accounts come over? Today the pane answers the first for one agent at a time, calls the built-in login “Default” or “discovered”, and says nothing about the import or about a saved choice that points at an account that is not there. This design answers all three on one screen.

PageWhat it shows
The paneThe whole pane in single-project mode: the import offer, one problem, the Defaults card, four agents stacked with every account, the built-in login named as such, an “In use” marker per agent, a hidden e-mail-shaped name and an agent with no accounts. Keyboard focus is drawn on “Copy 3 accounts”.
Import statesunknown with a count, unknown with none, declined, done (with and without new accounts), copying, copied, failed, not yet loaded.
Problems and statesBoth problem kinds, a hidden handle, two problems, after the fix; the e-mail-shaped label; agents with no accounts; loading, load error, hosted refusal; stale and partial data; the global layout.
PhoneThe pane and the import states framed at 375 px; what is cut first and what never is.

The decisions, each with its reason

  • Four agents stacked, not four tabs. Tabs showed one agent’s list at a time, so after an import a person saw one list and three hidden ones – the “did it fail?” reading. Stacked, each agent is a heading with one line of facts (installed, version, how many accounts, anything to fix) over its list; four headings scan in one pass on a laptop and in a few flicks on a phone, and a jump link from the top reaches the one that needs attention.
  • “In use” is a word in an outline badge, and the built-in login is named “Built-in login”. Both are words first; a check icon reinforces “In use”; no colour carries either. The old names “Default” and “discovered” described how xezar found the login, not what it is.
  • A problem shows twice: one line at the top, the fix inside its agent. The account it names has no row to sit beside, and the agent may be far down the page. Pending tone, never danger: the task still runs.
  • The import is a card once, then a line. The first offer explains the one cost (a committed file clones will see); after an answer the block shrinks so a decision is not re-pitched. A count of zero never gets a button.
  • Hosted mode renders none of it. The pane is already one refusal sentence there; an import button, a fix button or a CLI hint would be actions nobody on that page can take.
  • An e-mail-shaped name is “Name hidden” in the row, the picker, toasts, the confirm and problem sentences – identity stays opt-in behind Show details.
