Problems and the other states

A problem is a saved choice that names an account the list does not have. Nothing is broken – a task still runs, with the built-in login – so the pane shows it in the pending tone with words, never the danger tone, and puts the fix beside it.

1. Where a problem appears

Twice, on purpose. Once at the top of the pane as one line, because the agents are stacked and the affected one may be three screens down on a phone. Once inside that agent’s group, directly above its account list, with the fix. It cannot sit “next to its row”: the account it names has no row – that is the problem – and the row that IS in use instead is the built-in login, whose own “In use” marker is correct.

1a · where = defaults (single-project mode)

The project default for Claude Code names client-a, which is not in this list. Tasks use the built-in login instead. Fix: choose an account under Defaults for this project, or use the built-in login.

1b · where = selection (single-project mode)

This project’s own choice for Codex names work, which is not in this list. Tasks use the built-in login instead. Fix: choose an account in this project’s Agents settings, or use the built-in login.

Why “Use the built-in login” is a button. It is the one fix that is always valid and it is exactly what tasks already do, so pressing it changes no run – it only makes the saved choice say what happens. It goes through the existing selection route (profileId: null for the built-in login), which already refuses an unknown id. Choosing another account stays where it lives today: the Defaults card for 1a, the project’s Agents settings for 1b.

1c · the handle looks like an e-mail address – the name is left out

The project default for Claude Code names an account that is not in this list. Tasks use the built-in login instead. Fix: choose an account under Defaults for this project, or use the built-in login.

1d · pane-level line with two problems in two agents

2 account choices name accounts that are not in this list. Tasks still run, with the built-in login. See Claude Code, Codex.

1e · after the fix – the line goes, a toast confirms

Claude Code now uses the built-in login

Announced once. The pane-level line is a polite live region, so the drop from 2 to 1 is read; when the last problem is fixed the line is removed and the toast carries the news. Its first render is not announced – a page load is not a change.

2. A label that looks like an e-mail address

The collapsed row never prints it. The pane already treats who an account is signed in as as opt-in (“Show details” fetches identity only when pressed); a label someone typed as their address is the same fact by another road, and in single-project mode it sits in a committed file. The row reads “Name hidden”, keeps the folder (the folder is the account), and says how to see or change it. Show details reveals the stored label and offers Rename, as today. The same test decides a problem’s handle (1c). The test is the engine’s own looksLikeIdentity; the cockpit must not grow a second one that disagrees.

3. An agent with no accounts at all

An inline line inside the list frame, not a CenteredState: the page has its heading and three other agents, and a 72 px tile per empty agent would push them down for no information.

4c · hosted mode – refusal (unchanged sentence; no import, no fix, no CLI line)

Agent accounts

Agent accounts are managed from the machine that owns the checkout — this cockpit runs in hosted mode.

Absent, not disabled. Hosted mode already replaces the whole pane with this one sentence, which names who can act. The import block, the problem fixes and the CLI hint are all local-machine actions, so none of them renders – a greyed “Copy 3 accounts” would ask a question nobody on this page can answer. The server serves problems: [] in hosted mode and the import route answers 409.

6. The global layout

Global mode (no single-project root) keeps everything above with three differences: no import block and no file note; the marker reads “Default” instead of “In use”, because a machine default is what new projects get, not what every project runs; and the problem sentences name “The default for new projects” and point at “Defaults for new projects”. See open decision OD-3 and OD-4 in the README.
