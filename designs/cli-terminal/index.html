CLI terminal – live activity and one cockpit per project

What xez prints in a terminal: a short banner, one line per thing that happened, and a small live table of active tasks. Each project runs in its own xezar on a port it keeps. Words carry every state; colour only reinforces them.

Status: Draft, waiting for the first design review. Issue #467. The exact terminal output is in the text files below – this page only shows how the colours read in a light and a dark theme. Developer handoff: README.md.

Files

FileWhat it shows
tty.txtA terminal at 80 columns: first start, a second project, live activity with the table, more than 10 tasks, the stop summary.
tty-narrow.txtA terminal at 40 columns, and a resize from 80 to 40.
non-tty.txtOutput to a file, a pipe or CI: plain banner and one logfmt line per event.
quiet.txt--quiet, run --quiet and the four log levels.
error-cases.txtEvery refusal and failure: ports, a second instance, MCP, tasks, HTTP, skills, exposure, untrusted text, bursts.
multi-instance.mdOne cockpit per project: stored keys, port choice, MCP lookup, the project switcher, collisions and the compatibility entries.
open-questions.mdTwelve questions for the review, each with a recommendation.
switcher.htmlThe cockpit’s “Other projects” list in every state.

Colour key

Only the terminal’s 16 standard colours are used, so the person’s own terminal theme picks the shade. Here each one is shown with the cockpit token it mirrors. Switch the theme with the button in the bar.
