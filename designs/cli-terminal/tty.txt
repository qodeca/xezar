# Notes on scene 3
# - A continuation line (the URL, the wrapped HTTP reason) is indented to the
#   message column. It is part of the same entry and is never a new event.
# - The Time column is right-aligned m:ss, h:mm:ss after an hour.
# - “monitoring” is its own state word in the table. The summary line counts
#   it under running, like the cockpit’s Working bucket.
# - “1 failed since start” counts tasks that ended failed (b98de765). The
#   failed check at 10:12:08 is not counted: its task went on to a repair
#   step. See README.md § 6.3, “What failed counts”.
# - An HTTP entry shows the method, the route template (never the real path or
#   query) and the status, and on the next line the server’s own message in
#   quotes, cleaned and cut to one line (writing.md § 7: the server’s words,
#   verbatim). Request bodies and headers are never shown.
# - Token and cost parts disappear under XEZ_HIDE_TOKEN_USAGE=1 and
#   XEZ_HIDE_COST=1, exactly as in the cockpit.
