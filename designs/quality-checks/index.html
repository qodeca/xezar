Quality checks – UI design

A failing check means a task is not complete. Today that fact is hidden in a long list on a settings page, and a task can show a green "done" while a check never passed. This design moves the list to its own menu item with a live count, adds a real way to pass a check again, and labels every task truthfully.

Status: draft for design review (xezar-ux-design). Static mockup, not shipped code. Colours and type are copied from packages/web/src/styles/index.css. Sample data is based on this repository's live tasks on 2026-09-13. Developer handoff, full specs and copy deck: README.md.

Design decisions

DecisionChoiceWhy
Menu placeTasks, Inbox, Checks, Git, GitHub…Next to the other "what needs me" items. Git and GitHub are tools, not queues.
Menu iconShield with a tickTasks already uses the list-with-ticks icon. A shield reads as "guard", which is what a check is.
Badge numberFailing checks in this project; hidden at 0; 99+ capSame source and live stream as the Tasks badge, so it is always true. Hidden while loading or on error, never a guessed number.
Badge colourRedViolet in the menu means "someone wants you". Red means "broken", the colour of a failed task. Contrast is 3.8:1, higher than the shipped violet badge (3.1:1).
Page grouping"Can re-run" and "Cannot re-run"Grouped by the next action, not by age or check name. Each group tells you what to do in one line.
Card actionsRe-run check · Open task · ArchiveExactly the legitimate ways out. No dismiss, ignore or accept, as the leader spec requires (F-22, U-M06).
Check outputNot on the card; one click awayOutput can be long and can contain anything. The card shows the command and exit code; the task page shows the output.
Task statusRecord stays done; chip reads "done · check failed" with a red dotA new status value would break xezar run exit codes (BACKWARD_COMPATIBILITY.md §1). A new optional field is allowed.
After ContinueTask ends "done · check failed" and waits for a re-run (option A1)Continue keeps working as today. Automatic re-run after Continue (A2) is a separate, higher-risk change. Not yet confirmed by the owner.
ArchiveRemoves the task from the count; keeps the red label in ArchivedArchive means "dropped", not "accepted". History stays true. Not yet confirmed by the owner.
Settings pageKeep the rule and one live line; remove the card listThat page answers "what can the leader do". The list belongs where people go when something breaks.

Accessibility checklist for the build

  • Badge: the number is hidden from screen readers and replaced with words: "Checks, 6 failing checks".
  • Status is never colour alone: every red dot has words ("failed", "done · check failed") and every card has a warning icon.
  • The list is a polite live region: a check that fails or passes is announced without moving focus.
  • A disabled Re-run button has its reason as visible text under the card, linked with aria-describedby.
  • Motion (pulse, spinner, skeleton) stops under "reduce motion".
  • All actions work by keyboard with a visible focus ring; icon-only Archive has a label naming the task.
