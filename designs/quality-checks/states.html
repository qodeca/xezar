States

Every state the menu badge, a check card and the whole page can be in. Each state says what happened and what to do next. No state offers "dismiss", "ignore" or "accept".

1. Menu badge

The number is the count of failing checks in this project. It comes from the same full task list and live event stream as the Tasks badge, so it changes the moment a check fails or passes.

No failing checks – no badge
Inbox373 Checks Git

Zero hides the badge. A green "0" would be a second thing to read on every screen. Silence means healthy.

One, many, and the cap
Checks1 Checks12 Checks99+

Red, not violet. Violet in the menu means "someone wants you" (Inbox, unread tasks). Red means "something is broken" – the colour the cockpit already uses for a failed task. Screen readers hear "Checks, 12 failing checks".

2. Check card

One card per failing check. The card's first line is always the check name. The second line is the exact command. The third line is the task.

a · Failing, can re-run (default)

  • Quality gates

    bash .xezar/checks/repo-gates.sh --fast · exit 1

    Fix #197 – project-writer test fails outside a task temp dir failed Failed 2 days ago · 3 of 3 tries
    Open task

Why the output is not on the card: check output can be long and can contain anything. The task page already shows it in full. The card shows the command and exit code, which are enough to recognise the failure. "Open task" goes straight to the output.

b · Re-running

  • Quality gates

    bash .xezar/checks/repo-gates.sh --fast · running for 1 min 12 s

    Fix #197 – project-writer test fails outside a task temp dir re-running check
    Watch output

The card stays in the list while it runs. The check has not passed yet, so the badge still counts it. The badge drops only when the check passes.

c · Failed again

  • Quality gates

    bash .xezar/checks/repo-gates.sh --fast · exit 1

    Fix #197 – project-writer test fails outside a task temp dir failed Failed again just now · re-run 1
    Open task

    Same result as before. Re-running alone will not fix it. Open the task, read the output, and ask the agent to fix the cause first.

d · Passed (moment before the card leaves)

  • Quality gates

    bash .xezar/checks/repo-gates.sh --fast · exit 0

    Fix #197 – project-writer test fails outside a task temp dir running · Seal the gate evidence
Quality gates passed. The task continues with its next step.Open task

Passing is the only way a card clears on its own. The card turns green for about 2 seconds, then leaves, and the badge drops by one. The toast stays for 6 seconds, so a person who looked away still sees what happened.

e · Task is busy – re-run not possible yet

  • Confirm the task is not blocked

    bash .xezar/checks/worktree-preflight.sh --readiness · exit 1

    378: Independent QA of PR #378 (half 1 of #377) running Failed 14 h ago
    Open task

    The agent is working on this task. You can re-run the check when it stops.

Disabled buttons explain themselves. The reason sits under the card, not in a tooltip, so touch and keyboard users read it too. Archive is hidden because a running task cannot be archived.

f · Worktree removed – cannot re-run

  • MCP mutation gate (Stryker)

    npm run test:mutation:mcp · exit 1

    release-changelog bump: minor failed Failed 2 days ago
    Open task

    This check can no longer run: the task's worktree was removed. Archive the task, or start a new task for this work.

Archive means "this task is dropped", not "the failure is accepted". The task leaves the count. In the Archived list it keeps its red "check failed" label, so history stays true.

3. Whole page

Empty – nothing failing

No failing checks

Every check in this project's tasks has passed, or its task was archived. New failures show here, and in the menu, the moment they happen.

Loading

Loading this project's checks…

The badge shows nothing while loading. A guessed or stale number would break the "always true" promise.

Could not load
Could not load the checks. The connection to xezar was lost. This page reloads by itself when it comes back.

The badge hides on error, too. It never shows "0" when the real number is unknown.

Re-run refused by the server
The check did not start. The task started working again a moment ago. Wait until it stops, then re-run the check.

Plain reason plus the next step. Raw server errors never reach this screen.
