Task surfaces

The Checks page is not the only place that tells the truth. A task with a check that never passed must never look like a clean "done" – not in the task list, not on the task page.

1. Tasks list

Only the status chip changes. The chip keeps the cockpit rule: the colour lives in the dot, the words say what happened.

No new task status. The record still says done, so xezar run exit codes and every tool that reads the status keep working. The label comes from a new server field, unresolvedChecks. The "done · check failed" chip is sorted with failed tasks in "Needs you", not with finished work.

2. Task page

A banner under the title says, in one sentence, why the task is not complete, and offers the same two actions as the Checks page.

"Did not run" instead of "pending". After a task ends, "pending" suggests the step will still happen. It will not, unless the check is re-run and passes.
