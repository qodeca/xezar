Every state

Default, empty on first use, filtered to nothing, loading, error, refusal, stale or partial, already done, and the phone layout at 375 px. Every one has its own sentence; none of them is a spinner with no words. Switch the theme in the bar above — each state was read in both.

6. Refusal

Two refusals, and they are different kinds. The first is the mode refusing a surface that does not apply; the second is hosted mode refusing a write that must stay on the machine that owns the checkout.

/settings/global/projects · single-project mode

Projects are not managed here

This xezar runs in single-project mode: it serves this folder only, and adding, removing or switching projects is refused. To work on another repository, start xezar in that folder.

8. Already done

A person who starts xezar again in a folder that is already a single-project root sees exactly the default: the badge, their settings, their accounts. There is no "you are now in single-project mode" announcement, no dialog, no toast — the second run is not an event. The import ask happens once and only in the terminal (see the README: the ask is terminal-only, so this design draws no dialog for it).

9. Phone, 375 px

The mobile top bar carries the badge in its free data-slot="mobile-status" slot; the settings pane's file note wraps rather than truncating; the unavailable row stacks its actions to full width at 44 px. Nothing scrolls sideways at 375 px.

An empty frame means the browser blocks local iframes from file:// — open phone.html directly and narrow the window to 375 px instead.
