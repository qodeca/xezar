The two surfaces that hide the switcher

Add project and the sidebar's project groups already read the mode's capability. The composer's project pill and the command palette's Projects group do not — today they are gated on the registry holding more than one project, which is a different question with the same answer most of the time. Both must read the capability, because "the registry happens to hold one row" and "this xezar cannot have a second project" are not the same fact.

1. The composer footer

The pill row reads left to right as "in this project, run this skill, with this agent". In the mode the first pill is gone and the row starts at the source pill — which is the shape the composer had before multi-project, so nothing else moves.

Single-project mode

quick-task Claude Code sonnet Worktree

Removed, not disabled: acme-api — a picker whose only option is the current one offers nothing, and a disabled pill would invite a click that can never do anything.

The one thing to get right. Hiding the pill must not change where the task is sent. The composer still resolves its scope from /p/<id>/new — the pill is the control, never the source of truth. A build that drops the pill and the scope together would post a task to the wrong route with no visible symptom.

2. The command palette

Group order is fixed: Recently finished · Views · Projects · Tasks · Actions · Skills (patterns.md §7). In the mode the Projects group is not rendered at all — not rendered empty, and not rendered with one row pointing at where you already are. Every other group is unchanged.

3. Filtered to nothing

Typing the name of a project that is not this one is not a special case and gets no special message: it is an ordinary "no results", the same one any unmatched query gets. Inventing "there is only one project here" for that query would be guessing why someone typed a word.

No results.

4. What a keyboard user experiences

  • The palette still opens with ⌘K / Ctrl+K and still closes on Escape, returning focus to whatever held it.
  • With the Projects group gone, ↓ from the last Views row lands on Tasks or Actions — no empty heading to step over, because an empty group is never rendered.
  • In the composer, Tab order in the footer row starts at the source pill. Nothing is focusable-but-dead.
  • Both removals are absences, so nothing is carried by colour: there is no greyed-out control to interpret.
