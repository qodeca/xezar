The post-update offer

When the running xezar or the pinned setup templates differ from what this project last checked against, one row appears above the page. It states what changed, offers exactly two actions, blocks nothing, and does not come back for the same pair.

Why a status row and not an alert. Nothing is broken. In that row, the alert tone means an agent provider failed. Using it for "a version changed" would teach people to ignore the row that matters. The offer has no status dot at all: the sentence carries the whole meaning, and colour adds nothing to it.

One sentence shape, five situations

The same grammar covers an upgrade, a downgrade, a development build and a template-only change. The words "update", "upgrade" and "newer" never appear, because a downgrade and a development build are changes to look at, not permission to migrate.

What each action does

ActionWhat happensWhat is written
Re-check The button becomes "Starting…" and is disabled. A task starts in recheck mode from the bundled launch definition. The cockpit opens that task. The row goes away. The offer is recorded for the observed pair. "Last successfully checked" moves only when the task actually finishes its check.
Later The row goes away at once and focus moves to the page heading. Nothing starts. The offer is recorded for the observed pair, so restarting xezar on the same pair is quiet.
Neither — a restart Nothing appears. The recorded pair still matches what is running. Nothing.
Neither — xezar changes again A new pair, so the row appears once more with the new versions. The recorded pair is replaced and both timestamps are cleared for it, because a check of the old pair says nothing about the new one.

The offer while a re-check is running

Two clicks cannot start two checks. The row is replaced by a line that names the running task, with a way back to it.

Re-checking this project — open the task to answer its questions and accept its changes.

What the offer is not

  • Not a run. Nothing starts, and nothing is paid for, until a person presses Re-check or a leader calls for it.
  • Not a block. The page below is fully usable while the row is there. Tab order reaches the row first, then the page.
  • Not a nag. One appearance per version pair. Dismissing is remembered on disk, and a lost or deleted record simply means the row can appear once more — never that xezar stops working.
  • Not a promise. The row says a version changed. It does not claim your project needs anything; only the check itself can say that.
