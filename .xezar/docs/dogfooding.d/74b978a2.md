### 2026-09-20 — A red proof that stayed green, and a cache a unit test must never reach

- **The `key: maybeUndefined` guard needs to be asserted on the OBJECT, not on its JSON.** The
  AC-02 test for the new `tag` key checked `JSON.parse(JSON.stringify(entry))`, and
  `JSON.stringify` drops `tag: undefined` — so the test was green against exactly the break
  AGENTS.md names as the recurring contract-parity defect, and `npm run typecheck` was green too
  (`string | undefined` is assignable to `tag?: string` without `exactOptionalPropertyTypes`).
  Only the named red proof exposed it. The rule that follows: an "absent key" assertion must run
  against the value as well as its wire form, or it proves nothing about the shape.
- **`xezCacheDir()` is `~/.cache/xez` and no env var moves it**, so a unit test for anything that
  reads the team-skills bare clone reaches the developer's real cache by default — non-deterministic
  locally, empty on CI. Pinning `setActiveStateLayout(projectStateLayout(<temp>))` puts the cache
  inside the fixture and is the same switch single-project mode flips, so the test doubles as the
  AC-13 evidence. Worth knowing before writing the test, not after.
- **A recording `git` shim earlier on `PATH` is a cheap, real proof of "no network call".** The
  module runs `git` through `execFile`, so there is no runner to spy on; a shell script that logs
  `"$@"` and then `exec`s the real git turned "we believe this is local-only" into an assertion that
  no invocation matched `fetch|clone|ls-remote|push|pull`. Emptying `PATH` in the same way is the
  injection for the "git is not installed" degradation.
- **A developer's own git config breaks fixture repositories.** `git tag v1.2.3` failed with
  `fatal: no tag message?` on this machine because the user's global config annotates tags. Fixture
  setup now pins `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_SYSTEM=/dev/null`, which is the
  difference between a test that passes everywhere and one that passes on CI only.
