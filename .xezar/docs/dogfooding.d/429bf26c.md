- Observed: **the brief's own commands were among the false positives.** `grep -n "from '../core/" packages/xezar/src/workflows/run.ts` was refused (a quoted `..`-prefixed search pattern), and so was a `python3 - <<'PY' … PY` heredoc whose body quoted source text — a heredoc body is unquoted shell text, so the guard parses it as commands. A brief that asks for a quoted relative path or a heredoc should expect the refusal and route around it (`write`, or a variable), or the tokeniser has to learn heredocs.

The replacement reads a quoted string as a command only in a script position (`sh`/`bash`/`zsh`/`dash`/`ksh`/`ash`/`mksh`/`fish` with a `-c`-ish flag, and `eval`), which keeps that case green and drops the false positives. Inside the required set, `rm -rf '..'` is now allowed where `rm -rf ..` stays refused: a quoted `..` is the string a program receives, and only the quoting separates it from a listing token. The header's cannot-see list names the first; the second is the price of the criterion and is stated in the PR body.

- Observed (round 1 review, PR #693): **measuring a replacement by deleting the old code measures it against the suite, not against the command space.** Deleting the blanket flatten pass went red on exactly 1 of the 106 existing cases, which correctly identified what that pass was load-bearing FOR (quoted shell scripts) — but those 106 cases were written for the OLD guard, so they could not contain the commands the new code would get wrong. The replacement shipped with two holes the deletion experiment was structurally blind to: `bash -o pipefail -c '<script>'` (the flag's separate argument stops a dash-word scan before the `-c`, so the script was never read, and five spellings that BLOCKED on `main` came back ALLOWED) and a quoted `..` exempted for every command (`rm -rf '..'` reaches the worktree's parent — every peer run's tree). Lesson: a red count from deleting the old mechanism says which OLD cases depended on it; it says nothing about the new code's own failure modes, so a second, adversarially-built table is a separate artefact to write before claiming the replacement is equivalent.
- Observed (round 2, scoped re-check of PR #693): **a fix that is right about the OLD mistake can be wrong about the same word.** Round 1's Blocker was "a dash-word scan stops before the `-c` and reads the flag's UNQUOTED argument (`pipefail`) as the script". The repair decoupled "was a command flag seen anywhere in the segment" from "which word is the operand" and then took the FIRST QUOTED word in the segment — which is the same mistake with the quoting flipped: `bash --rcfile 'x' -c '<script>'` hands the flag a QUOTED argument, that argument is now the first quoted word, and the real `-c` operand is never read. Both versions answered "which word is the script" without reference to WHICH FLAG asked for one. Lesson: when a fix relocates a search, state what the search is anchored TO; an unanchored "first word that looks like X" survives one adversarial table and fails the next.

Anchoring at the command flag closes 16; `-co 'pipefail' '<script>'` needed the second half, stepping over a known flag's own argument PAST the anchor. A two-row bug report is a sample of a class, and the cheapest way to find out how big the class is, is to write the table.
