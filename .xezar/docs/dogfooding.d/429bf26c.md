- Observed: **the brief's own commands were among the false positives.** `grep -n "from '../core/" packages/xezar/src/workflows/run.ts` was refused (a quoted `..`-prefixed search pattern), and so was a `python3 - <<'PY' … PY` heredoc whose body quoted source text — a heredoc body is unquoted shell text, so the guard parses it as commands. A brief that asks for a quoted relative path or a heredoc should expect the refusal and route around it (`write`, or a variable), or the tokeniser has to learn heredocs.
- Observed: **naming what the blanket flatten pass was load-bearing FOR made the (B) fix a measurement, not a judgement call.** Deleting `wordsEscape(shellWords(command.replace(/["'`]/g, ' ')), roots)` failed exactly ONE of the 106 existing cases — `blocks sh -c with a quoted script` — so the pass's unique value is quoted shell scripts and everything else it caught was incidental. The replacement reads a quoted string as a command only in a script position (`sh`/`bash`/`zsh`/`dash`/`ksh`/`ash`/`mksh`/`fish` with a `-c`-ish flag, and `eval`), which keeps that case green and drops the false positives. Had the experiment shown five failures, the fix would have been a different, narrower one.
- Observed: **the loosening this buys is real and is written down rather than hidden.** Quoted text is no longer re-read as a command, so `perl -e 'unlink "<primary>/tracked.md"'` now passes (it is one argument to a program that builds its own paths — already on the guard's documented cannot-see list) and the issue's "prose naming a repository path" case passes. Inside the required set, `rm -rf '..'` is now allowed where `rm -rf ..` stays refused: a quoted `..` is the string a program receives, and only the quoting separates it from a listing token. The header's cannot-see list names the first; the second is the price of the criterion and is stated in the PR body.
