### 2026-09-20 — #677 wave 2 B4: the provider switch through the MCP

- A four-slice sequence pays off in author time. B4 copied B1–B3's shape file for file (door key
  set from a contract shape, route decides the values, one narrowing helper shared with the read,
  `operationId` on every write row, one audit row per write, `mcp-api.json` regenerated with `-u`),
  and the whole slice took one authoring pass with no gate return. The slices that describe their
  own pattern in comments — `workspaceConfigWriteSchema`'s "the door decides the KEY SET" paragraph
  — are what made that possible; a reviewer's sentence written into the code is worth more than the
  same sentence in a merged PR body nobody re-reads.
- The spec's five named breaks did not all fit the slice, and saying so beats forcing them. Break
  (2) is "a hand-built body that skips the route validator → the 400-parity test red", which assumes
  a route bound on a VALUE; these two routes bound only types, so there is no body the door can pass
  and the route refuses. The honest equivalents were run instead — a hand-built incident id, and the
  route's reason rewritten at the door — and both went red on the cases that matter. A named break
  that cannot exist in a slice is a finding about the slice, not a reason to skip the proof.
- Scratch-copy red proofs (`cp file file.bak`, break, run, restore) worked cleanly for five breaks
  across three files and never touched the shared stash. Two of the five reds were crashes rather
  than assertion failures until the break was made more faithful — deleting an action from
  `REFUSED_ACTIONS` without giving it an `ACTION_FIELDS` row throws inside the schema instead of
  failing the refusal assertion. A red proof that crashes proves less than one that fails the
  assertion the case is about; it is worth the extra minute to break the code the way a careless
  change would.
- One pre-existing flake surfaced by running the suite rather than by reading it:
  `audit-four-doors.test.ts` asserted a temp folder's basename never appears in the audit trail,
  while the project id is a lowercase SLUG of that same basename — equal whenever `mkdtemp` drew an
  all-lowercase suffix, roughly one run in thirty. It cost one debugging cycle in this run. The
  lesson is narrow and reusable: an assertion of the form "this random value never appears" needs a
  value that cannot be derived from anything the system writes.
