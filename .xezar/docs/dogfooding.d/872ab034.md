### 2026-09-21 — MCP test fixtures pin HOME so the developer's skill catalog cannot leak (#671), `bug-fix` step `Reproduce, diagnose and fix`, `xezar-bug-investigation`, pi — real-task observed, fixture-tested, live-verified on the failing machine

- Input: the gate-return diagnosis for run `dd76265e` (PR #783) and the PR's author note. Both were correct and reproducible here: `npm test -- packages/xezar/src/mcp/tools/task-create.test.ts` was 2 failed | 115 passed (117) with the developer's real `~/.agents/skills/xez-issue-create/SKILL.md` present, and 117 passed under a throwaway `HOME`. The diagnosis alone would have left this failing on every local gate run; the brief's bounded fix is what closes it.
- Observed: the pin cannot live in a fixture's `setup()`. `skills.ts` resolves its two global skill dirs from `os.homedir()` ONCE, in the module-level `GLOBAL_SKILL_DIRS` const, so by the time a fixture assigns `process.env.HOME` the paths are already fixed. The fix is therefore a module-load side effect, and the shared testkit has to be a test file's FIRST import — an import-order contract, not a helper call. The diagnosis's "the fixture pins XEZ_HOME but not HOME" was accurate but incomplete about the mechanism; the module-load timing is what chose the shape.
- Observed: the brief asked for the pin in "the shared testkit the MCP tool tests already use". No such MCP tool fixture existed. The one shared testkit most MCP tool tests import, `operation-id.testkit.ts`, is imported after `server.ts` in every one of its 13 importers, so a module-body pin there would have run too late to be a guarantee. A dedicated `mcp-test-home.testkit.ts` was created and imported first in all 27 MCP test files that build a project workspace or read the skill catalog.
- Observed: `packages/xezar/src/state-path-scan.test.ts` deliberately skips `.test.ts`/`.testkit.ts` ("a fixture legitimately builds a fake home"), so a testkit that reads `process.env.HOME` is not a product-code finding and needed no allowlist entry.
- Red proof (scratch copy, never `git stash`): pin removed + a scratch HOME carrying `.agents/skills/xez-issue-create/SKILL.md` -> the two named cases fail at `task-create.test.ts:978` (`findIssueCreateSkill` returned the global skill record) and `:985` (`startBodies` carried `skill: xez-issue-create` instead of `workflow: quick-task`); the same tree with the pin -> 117 passed.
