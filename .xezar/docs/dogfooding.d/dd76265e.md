### 2026-09-21 — PR 4 of #467: linking out, and the two questions a predicate must not merge

- Input: the accepted spec's `### PR 4 — the cockpit: link out` plus § 3–4 and the appendix, read
  read-only from run `a0cc9e46`'s evidence directory, with PRs 1–3 already on the base. Deliverable:
  the third project-mode predicate, the sidebar's Other projects band, the palette's link-out rows,
  the global Tasks note, three red proofs and the design-system entries.
- The brief named the temptation before I met it: fold `instanceMode === 'project'` into
  `projectsLocked`. All three predicates read like "this cockpit is narrower than the default", and
  the merge compiles, types and looks tidy. What it actually does is delete the Add project control
  and the whole Projects group — `BACKWARD_COMPATIBILITY.md` calls that a break. The red proof took
  four minutes and is the only thing that makes the refusal auditable rather than a matter of taste.
- The byte-identity pin for the untouched default path had no precedent here: `packages/web` carried
  no snapshot test at all before this PR. A committed `.snap` of the sidebar's `outerHTML` is what
  makes "one class moved" fail; the break proof moved `px-2.5` to `px-2` on the flat nav and the
  snapshot caught it. The cost is honest — a legitimate sidebar change now needs `-u` — and that is
  the point of the criterion.
- Two test-harness defects of my own, both found in self-review and both the same shape:
  `expect(optionalChained).not.toBeNull()` passes for `undefined`, so a `waitFor` resolved on the
  first tick with nothing rendered and the assertion after it read a value that was never there. A
  `?? null` fixes it. Worth knowing because the test still went green on the fix under test — it was
  green for the wrong reason.
- `window.location.assign` cannot be spied on in jsdom (`Cannot assign to read only property`), and
  `Object.create(window.location)` does not help. `vi.stubGlobal('location', { href, assign })` with
  a plain object does, because `window === globalThis` there.
- Browser spec deliberately not written: the suite shares one instance and one set of on-disk
  fixtures, and this feature needs a server booted in a different instance mode, which no shared
  boot can provide without changing what every other spec sees. Recorded in CAPABILITY and in the
  PR body rather than left as a silent gap.
