### 2026-09-20 — #677 wave 2 B5: agent accounts through the MCP (Claude Opus 5, run e212dc2a)

- The slice brief called `check_account_status` one of "the five account writes", and the repository
  disagreed for a reason worth keeping: its cockpit counterpart is a `GET` with no audit descriptor,
  and `audit-inventory.test.ts` classifies an MCP action by the route its door dispatches. Making it
  a write would have claimed a cockpit audit row that is never written. It shipped as a read, with
  `operation-id.test.ts`'s written exemption saying why — the kind of disagreement a brief cannot
  settle and a test can.
- The brief's red proof 3 ("leave the action in `AUDIT_MCP_READS` → `audit-inventory.test.ts` red")
  had no subject in this slice: the four account writes already had inventory rows and were never
  reads, so nothing left that list. The proof was run in the opposite direction instead — moving
  `create_account` INTO `AUDIT_MCP_READS` — which proves the same classification rule against the
  new actions. A named break that does not exist in a slice is better re-aimed than reported green.
- The first design of the two account reads looked the account up in the listing before dispatching,
  to build the `default:<provider>` route id honestly. In hosted mode the listing is EMPTY by
  design, so the door answered "no such account" where the route would have answered its own 409 —
  a pre-flight read that turned a policy refusal into a nonsense one. Removing the lookup and
  letting the route answer made the hosted pin work and cut a request per call: at a door whose
  whole claim is "the route decides", a convenience read before the route is a second opinion.
- `packages/contract` already held non-strict twins of four schemas `server.ts` declared strictly.
  Moving the routes onto the contract's copies meant making the contract strict and carrying the
  `update` refinement across — behaviour a type cannot hold. Zod 4 keeps `.shape` through
  `.refine()`, which is what let the request-parity guard keep reading the key set.
- Three hand-written counts in three files track the inventory's covered records (106 → 109), and
  each fails separately. They are cheap to fix and easy to miss; a slice that flips a status should
  expect all three plus the two published tables in `mcp-parity-coverage-map.md`.
