### 2026-09-21 — a review response that had to cross the client/server seam (#790 round 1, #796)

Observed in this run, `address-review-findings` on PR #790 at `6ed0ec90`.

- **The QA role found what three green gates and two APPROVEs could not.** Code review (APPROVE)
  and design review (PASS) both read the band as correct, because it IS correct — as a function of
  the data it is handed. The defect was that nothing ever handed it new data, and only the role
  that drove two real cockpits side by side and waited 75 seconds could see that. The lesson is not
  "review harder": a frozen surface is invisible to any reader of one revision, so the kit's
  separate live-QA role is the control that catches this class and a faster pipeline without it
  would ship it.
- **The brief naming the mechanism saved a round.** The finding said what was wrong; the leader's
  brief said which mechanism the repository already has for it (the topic bus, demand-driven, no
  `refetchInterval`) and named the two files. That turned an open design question into an
  implementation, and it is the same content AGENTS.md § Real-time events already carries — the
  brief's value was pointing at it before the author started, not adding anything new.
- **`git stash` really is the wrong tool here, and a scratch copy costs nothing.** Three named
  breaks were proven red this way: copy the file to the run's evidence dir, record its sha256,
  apply the break, run, restore, re-check the sha256. Two minutes, no shared stash stack, and the
  restore is verifiable rather than assumed. This worktree shares its stash stack with every other
  task on the machine, so the alternative was never safe in the first place.
- **A test that passed either way would have been easy to write.** The band's red proof asserts DOM
  state words after a pushed frame; with the subscription removed it goes red, which was checked
  rather than assumed. The first version of it failed for an unrelated reason — TanStack batches
  its notifications, so a synchronous assertion after `act` reads the old DOM — and the temptation
  at that moment is to conclude the fix is broken. It was the assertion. Isolating that in a
  five-line throwaway probe (direct `setQueryData`, same failure) settled it in one run.
