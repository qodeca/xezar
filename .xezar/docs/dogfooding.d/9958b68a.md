- Observed: **The eight red proofs cost less than the harness to run them.** All eight named breaks (B1–B8)
  were applied to a `cp` backup of `run.ts` by one small node script with literal source anchors,
  each with the single test selection that must go red, in one loop of about four minutes. Two
  things made that cheap and are worth reusing: `scriptedRunner` in
  `packages/xezar/src/workflows/engine-incidents.testkit.ts` already records every `AgentRunSpec`,
  which is exactly the observation a spawn-shape change needs, and the bundled dry-run mock's
  `XEZ_MOCK_ARGS_FILE` hook lets a test assert `--resume` reached the real CLI argv. Neither had to
  be built.
- **`git stash` is the wrong tool here and the skill is right to ban it.** The stash stack is shared
  with every other worktree on this machine, and eight applications of a break is eight chances to
  pop a peer's work. A `cp` of the one file under change is strictly simpler and has no shared state.
- **Two eligibility conditions could not be checked in one place, and saying so in a comment was the
  honest fix.** Five of the six conditions for the cheap return are decidable in the workflow loop;
  the agent-account (`profileId`) one is only known after `agentEnvForStep` resolves inside the step
  spawn. Rather than pretend otherwise, the re-check lives there with a comment naming why, and its
  fall-back emits a `note` — the spec's own warning was that a silent fall-back to a fresh session
  is the failure mode this whole path exists to avoid.
- **Forcing a negative case needed a store listener, not a new seam.** "No recorded session" and "a
  session on another backend" are states the engine never produces itself, so the test mutates the
  step record from a `store.on('run')` handler the moment the gate step starts running. That kept
  both breaks testable without adding a test-only hook to `run.ts`.
