- **Every one of the three Majors was the same failure wearing three coats: a branch that reads "resumed fine" when nothing was resumed.** A backend that ignores `spec.resume` (OpenCode), a backend that refuses the id at runtime, and an account mismatch nobody tested. The round-1 lesson is the AGENTS.md fail-open rule read one level deeper: it is not enough to pair a silent pass-through with a test for the empty-input case, because the eligibility question itself can be answered from the wrong evidence. A recorded session id is evidence that an id was minted, never that the runner will reopen it. Decide from what the runner can do.
- **The reviewer's red proof was worth more than the author's eight.** The author's B1–B8 all broke code that existed; the reviewer's probe scripted a case the code had no branch for at all (`error: 'No conversation found with session ID: …'` on the resumed turn) and got `status=failed`, 2 spawns. A break-the-code proof can only pin what was written; a script-the-environment proof finds what was not.
- **A second execution inside one step is a closure, not a loop counter.** The runtime fall-back re-runs the step's own spawn-and-await once, so that body became a local `execute()` and the mutable turn state (`sessionError`, `lastTurnText`, `turnText`, `sawActivity`, `startTokens`) is reset between the two calls. What made it safe to bound was naming what must NOT be retried: a cancel, xezar's own memory-guard pause, and — the important one — a resumed turn that produced text or a tool call and only then failed.
- **A Minor that says "INFERRED, not executed" is a reading assignment, and it paid.** The reviewer's guess that Codex double counts tokens on a resumed thread was right, and reading four runners settled it in minutes: three accumulate from zero per session object, Codex reports the thread's cumulative total. The fix is one list beside the resume policy, and the test that pins it needed one new optional field on the shared scripted runner.
