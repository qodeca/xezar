### 2026-09-20 — A guard that read the task where the product reads the step

- The Major of the #742 review is a shape worth naming, because nothing in the authoring run could
  have caught it. The independence guard resolved "what did the reviewer run on" from
  `RunRecord.runner`, copying the ORDER the cockpit's own `taskRunner` uses — and that order is
  correct for the question the cockpit asks ("what is this task's engine") and wrong for the
  question the guard asks ("what engine produced THIS report"). Both readings are defensible in
  isolation; only "a mix per step" — a headline product feature, stamped per step in
  `workflows/run.ts` and named by the verdict's own `stepId` — decides between them. The lesson is
  the § Changing a mechanism that already works rule in its other direction: before copying a
  resolution order, name the QUESTION the original was answering, not the fields it read.

- Every fixture in the authoring run was single-backend, so the guard passed 16 green tests while
  failing open on the case it exists for. A policy guard's first fixture should be the mixed case,
  not the ordinary one: the ordinary case is the one that cannot distinguish a correct guard from
  an absent one.

- The reviewer's m1 asked for "the engine's one canonical model mapper" so aliases compare equal.
  Reading the engine said half of that is impossible on purpose: `model-identity.ts` normalises
  provider form and whitespace, but `claude-model-catalog.ts` deliberately does NOT surface a
  CLI-resolved id, because pinning xezar to one re-creates the drift it exists to avoid. So the fix
  uses the canonical mapper AND states plainly, in the argument description and in
  BACKWARD_COMPATIBILITY.md, that a tier alias and its pinned id are different names and are not
  collapsed. A guard that is documented as weaker than a reader would assume is worth more than one
  that quietly invents vendor knowledge to look strong.

- The red proofs were taken by copying the fixed source aside, restoring the PR-head file in place,
  running the new tests and restoring by byte-compare — no `git stash` anywhere near a stash stack
  shared with every other worktree on this machine. Nine tests red, including the two rendering
  cases the quoting change rewrites; the fixed file's sha256 was recorded before and matched after.
